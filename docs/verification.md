# Результати фінальної локальної перевірки

Перевірено 2026-11-06 перед оглядом користувача. Публікація та деплой не виконувалися.

## Автоматичні перевірки

- pytest на PostgreSQL: 75 тестів пройдено, включно з конкурентними обмеженнями, без SQLite.
- Ruff check та Ruff format check.
- Alembic upgrade із порожньої БД та check на відповідність моделям.
- Невалідний Unicode CSRF-токен тепер дає 403 замість 500; додано регресійну перевірку.
- Git не відстежує `.env`, ключі, `.venv*`, `.idea` чи QA-скриншоти.

## Перевірка обсягу

`tests/test_capacity.py`: 550 запитів при конкурентності 10, серед них 500 різних
подій та 50 дублікатів. Збережено рівно 500 подій і 500 generation jobs.
На цій машині p95 приймання — 58 мс, максимум — 126 мс; вимір через ASGITransport
без зовнішньої мережі. Це локальний результат, не гарантія часу для довільного хостингу.

Два worker з контрольованим LLM обробили всі 500 jobs. На кожне вікно дозволено
не більше 60 допусків. Межі вікон прискорювалися переведенням timestamps лише в
тимчасовій тестовій БД; це не десятихвилинний production benchmark.
Реальні платні LLM-запити під час масових перевірок не виконувалися.

## Чистий Compose та браузер

Створено окрему копію відстежуваних файлів без `.env`, `.git` і локальних середовищ.
Compose запущено під окремим project name з новим PostgreSQL volume та окремими портами.
Міграції, API, worker і mock-helpdesk стартували успішно.

Перевірено: вебхук → реальна безключова спроба LLM → чернетка → HTML-форма approve
→ доставка з `accept-timeout` → одна прийнята відповідь. Основну БД не очищали;
після перевірки видалено лише тимчасові контейнери й том окремого project name.

У headless Microsoft Edge відкрито інтерфейс із чернеткою на ширині 1280 та 390 px.
Скриншоти обох розмірів переглянуто: читабельний текст, доступні кнопки, немає
горизонтального overflow або JavaScript-помилок. Скриншоти залишені поза Git.

## Межі перевірки

- Платний OpenAI-режим перевірений контрольованими HTTP-відповідями; доступність моделі
  з ключем власника акаунта не перевірялася. Безключовий режим перевірено реально.
- Відсутність дубля після таймауту залежить від надійного Idempotency-Key на стороні
  хелпдеску. Мок його реалізує; довільне зовнішнє API може не підтримувати цю гарантію.
- Глобальний ліміт у БД стосується допусків до LLM-обробника; довільна пауза ОС між
  допуском і HTTP-викликом може змінити фактичний час запиту.
- Перед публічним деплоєм потрібні власні секрети, HTTPS, правильний PUBLIC_BASE_URL
  та довірений allowlist. GitHub-публікація — після погодження користувача.
